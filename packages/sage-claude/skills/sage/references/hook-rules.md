# The sage hook's rules

What the sage hook allows and refuses in sage mode: the logbook, the commands of an agent and of the chief, and the program words.

Only the chief writes the logbook. The sage hook lets an agent run only `status`, `merge-check`, `logbook`, `standing` and `config` without `key=value`: `node <path>/sage.mjs <command> [--project <path>]`, with the copy of sage.mjs that the hook loads, also in a pipe or a chain. The hook judges the programs that a command line runs (T815): `node` or the script itself that runs `sage.mjs`. Any other program may read its files. The hook refuses an agent's file change under the sage root in any case or Unicode form, and an agent's shell write whose literal path is in the sage root or the shared root: a word of a program that is not a reader (`cat`, `grep`, `echo`, `jq` and the like), the value of a `key=value` or an `--option=value`, or a redirection's target, resolved from the program's folder (also after a literal `cd`, `pushd` or `popd`, and `~` as the home folder) as written, not through a link (so `rm` of a link to a root removes the link and passes), or a word whose text holds a root's path. A pattern counts by its literal part, the text before its first `$`, backtick or pattern character, so `rm dist/*` and `jq ... > config.json` pass in a project. A remove or a move (`rm`, `mv`, `rsync --delete`) of a folder that holds a root is refused too, also by a pattern in it (`rm -rf ~/.claude`, `rm -rf ~/*`). A refusal names the word that caused it, in the command's own capitals. When the hook cannot read a line, it refuses it only when its text names a merge, a push, the state tool, `gh`, `git stash` or a process program. When the hook cannot check an agent's call, it refuses it. A variable, a substitution, a path through a link, code (`node -e`, `python -c`), a script and text piped into a shell can still build a path or a command while the line runs: that is a limit of the hook, and the sandbox (tasks T94–T99) is the full guard.

Only sage.mjs changes the logbook, so that each change leaves its record. The hook refuses the chief's Write, Edit, MultiEdit and NotebookEdit under the sage root, in any mode. It also refuses the chief's shell write (a redirection to a file, `cp`, `mv`, `rm`, `sed -i` and the like) whose literal path is in the sage root or the shared root, by the rule above for an agent. A logbook file's name elsewhere (`tasks.tsv`, `config.json` in a project) passes. The state tool passes, and so does a read of the logbook, also in a pipe or a chain. The user's own `!` commands are not hook events, so the user can still change a logbook file by hand.

For agents and the main session in sage mode, the hook refuses `{`, `[`, `*` or `?` in program words, the first git/gh subcommand, and the subcommand after `gh pr`, except the literal `[` and `[[` test commands; ordinary arguments are allowed.

## What the hook refuses an agent

- `git stash` in any form, also with `-C` or `--git-dir`: every worktree shares one stash list. Use `git worktree add --detach <scratch> <sha>` or `git show <sha>:<path>`.
- A program that lists or signals processes (`ps`, `pgrep`, `pkill`, `kill`, `killall`, `lsof`, `top`), unless it resolves to a fake in the temp folder. Put a fake `ps` first on PATH that prints a start time in the past, and run a fake `kill` by its path. The chief is not limited.
