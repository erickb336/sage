**Approvals in Codex.** In Codex's default sandbox, `.git` is read-only and the network is off. So each git write (for example `git worktree add` and `git commit`) and each network step asks the owner for approval, at least 5 clicks in each small task. When the sandbox refuses such a step, run the same command again with escalated permissions, and wait for the owner. The exception is `git worktree add -b <branch> <path>`: first run `git branch --list <branch>`. If it prints the branch, the failed step left it, so run `git worktree add <path> <branch>` with escalated permissions and no `-b`. If it prints nothing, run the same command again with escalated permissions. A sandbox refusal is not a failed task. When the approval policy is `never` or the owner says no, report STATUS blocked and name the step.
