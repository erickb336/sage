**Approvals in Codex.** Read the active sandbox and approval policy. Do not assume that `.git` or the network is unavailable. Run authorized work within that policy. With approval policy `never`, never request escalated permissions.

A refusal is not a failed check. Stop the denied action; do not retry through another tool, command form or permission level. Continue independent allowed work. A refused progress message does not cancel permitted edits or checks. Report the denied action and unchecked behavior under NOT VERIFIED. Use STATUS blocked only when the refusal leaves required work unfinished.

If an authorized worktree command returned an uncertain result, inspect `git branch --list <branch>` and `git worktree list` before any permitted continuation. Do not recreate or replace existing work.
