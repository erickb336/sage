# A shared logbook

Each row gives a command of the sage state tool and its full rules. Run each as the sage skill says: node, the state tool's absolute path and the command, without quotes.

Each write names its chief (the sage skill has the rule). A write on a task of another chief refuses and names that chief. A command with no chief only reads. A legacy logbook refuses both options, `claim`, `offer`, `cancel`, `accept`, `unclaim` and `gate replace`.

| Command | Does |
| --- | --- |
| `link --to <folder>` · `link --separate` | Run it only after the user's answer in the chat. `--to` adds a row for this checkout to `bindings.tsv` in the shared root, for a logbook of that root. `--separate` makes a new shared logbook and a row. The folder name stays `<slug>-<6 hex>` and is saved in the row. A retry changes nothing. A project with a legacy logbook in either provider root refuses, because a link would hide its tasks: only the move takes it over. A logbook belongs to its oldest row with first commits whose checkout is still on the disk, or its oldest such row when all are gone. A checkout with no row and no logbook, with the first commit of a shared logbook (a moved checkout, a clone or a fork), refuses every command and `init` and names the link; only the first-commit call on the way to that refusal runs at a read. A `--to` to a logbook whose owner has no first commit in common with this checkout refuses; a shallow clone needs `git fetch --unshallow` first. A row that names a missing folder, or a row with no first commit in common with the owner, refuses every read and write of that checkout only, and link replaces that row. The first-commit call is the hardened local read. A timeout, or a repository that Git cannot read, refuses and makes no row. Only a HEAD with no commit yet, or a folder with no `.git` entry in it or above it, has no commits. An unwritable shared root, or a provider root that link cannot read, refuses and names the path. A damaged `bindings.tsv`, or a missing one that `bindings.made` says sage made, refuses every project, and sage never falls back to a legacy logbook. The shared root is the launcher's option, `SAGE_SHARED_HOME` (an absolute path), `<SAGE_HOME>/shared`, or `~/.sage`. For a shared project, `cycles.*` and `max_rounds` live in the shared root's `config.json`: the first shared write takes the largest value of the provider roots, and a later link leaves them. Model keys, `arena`, the caps and `.hooks` stay in the provider root. |
| `move --preview` · `move --plan <plan>` · `move --gate <G>` | The move of an existing project into one shared logbook, when the user asks for it. 1. `--preview` only reads: show its print to the user as it is. It refuses, with nothing changed, while a run runs, while a provider's plugin is below contract 2, or when a folder cannot be written. Then start no new run in the project, and tell the user what the refusal says. 2. `--plan <plan>` with the 8 hex of the preview's plan opens the move gate in this logbook and prints it: put it to the user word for word, with your recommendation. It refuses when the logbooks changed since the preview. 3. After the user's answer (`gate answer`), `--gate <G>` moves: it checks the plan again under the locks, then prints six steps, the end check by table and provider, the map page, the backup paths and the restore steps by hand. Give the user the end check, the map, the backups and the restore steps with the warning first. A plan that no longer matches moves nothing and says what changed: show a new preview and open a new gate. A move gate answers once; keep moves nothing. While a move's plan is saved, every command of the project in either provider refuses and names `sage move --gate <G>`: run it at once, from any checkout of the move (the user's answer covers it), and tell the user. An end check that does not match names no command: show the user the missing records and the steps to set the plan aside, start no work in the project, and wait for the user. The move takes the open tasks of the Claude and Codex logbooks of the repository, also of its clones, with new numbers (Claude's first) and an adoption record of version 2 that keeps each branch and PR. Each moved task starts unclaimed; one in verifying, verified or pr-ready returns to reviewing. Runs, verdicts and kept reports stay in the old logbooks, which become read-only. Writes the user's "unused" answer for a provider with no row in `plugins.tsv`: then the gate offers that answer in place of a plain move. |
| `claim <T> --version <version> --chief C<n>` | Shared logbook only. Gives a task with no owning chief to this chief. A write on such a task refuses and prints this command, with the version. A task that changed, or that another chief claimed first, refuses. A chief claims only a task that it unclaimed itself, or, after the move, a task that its own provider started: a task that another chief unclaimed last, or that the move brought from the other provider's logbook, refuses and names the takeover gate. Any chief abandons a task with no owning chief with no claim: `task <T> set state=abandoned --why "<reason>" --chief C<n>`, with that state alone. The task keeps no chief, and the decision row keeps the reason and the chief. |
| `offer <T> --to C<n> --chief C<n>` · `cancel <T> --offer <id> --chief C<n>` · `accept <T> --offer <id> --version <version> --chief C<n>` · `unclaim <T> --chief C<n>` | Shared logbook only. `offer` names one other chief, and the owning chief stays until that chief accepts. A task has one open offer. `offer` and `task <T>` print the offer's id and the version. `cancel` clears the exact open offer, also while a run is active, and a cancelled offer never becomes valid. The chief that the offer names runs `cancel` to decline it: the line says that it declined, and the owning chief keeps the task. `accept` does not take the task: it opens a takeover gate from the owning chief to the named recipient, and the owner's answer approve gives the task, as for `gate replace`; the answer decline ends the offer. A second accept prints the open gate and opens no other. Its line ends with the next step: ask the owner to answer the gate. It needs the exact open offer, the current version and no active or unknown run. A run that ends changes no task, so the recipient still accepts, and a transfer changes no run. `unclaim` clears the owning chief, and only that chief claims the task back; another chief takes it through the takeover gate. It needs no open offer and no active or unknown run. Its work and reports stay. |
| `gate replace <T> --to C<n> --chief C<n>` | Shared logbook only. The takeover gate: the owner gives a task to another chief, in either direction between Claude and Codex, and no chief takes a task from another chief without it. Any chief opens it for a task of another chief, for a task with no owning chief that it may not claim, for an owning chief that stopped, or for a session that `/clear` made a new chief. `accept` opens the same gate. A gate that is open already for the same task and chiefs is the one: no second one opens, and the line prints it. It has the options approve and decline (a gate of an older sage has replace and keep, and still answers). Its question asks "Hand <T> and PR <n> from <chief> to <chief>?": it names the task, its PR, the owning chief (or the chief that unclaimed the task, or the logbook that the move brought it from) and the new chief with their providers, each active or unknown run with its role, what each answer does, that the branch keeps its name, the PR its number and the verdicts stay, and, last, the task's title. When a Claude chief takes a task from a chief of another provider, the question says that it runs one fresh cycle before it merges, and the merge check and the board keep that rule: the cycle counts only the verdicts of review and QA runs that started after the owner's answer. It is the only way to take a task with no consent from its chief. Each line that opens it ends with the next step: ask the owner to answer it. The owner's answer goes through `gate answer`, as for every gate. A chief never answers a takeover gate by itself: only the owner's answer counts. This rule is an instruction, not a check. Option 1 sets the chief, clears an open offer and ends each of those runs as failed, in one write. It refuses when the owning chief changed, or when a new run started: answer decline, then open a new gate. Decline and the owner's own words change nothing, and the line says so: `nothing replaced`, the task keeps its chief, and the gate is spent. A decline of a gate that `accept` opened also ends that offer in the same write: its question and the line say so. Never report a replacement from that line. A takeover gate answers once. When another worktree of the repository holds the task's branch, the answer's line names it and the one safe command that frees it (`git -C '<worktree>' switch --detach`, the path quoted for a POSIX shell, never `--force`), then says that the new chief checks out the branch in its own worktree. A path with a control character gets no command: the line says to find the worktree with `git worktree list`. The replaced chief gets a refusal that names the new owning chief. A run that ended as blocked or failed keeps a late report once, with its arrival time, and `task <T>` prints its path. That report backs no verdict. |
| `chief name C<n> <name>` | Shared logbook only. The owner's act, so it names no chief. Gives chief `C<n>` a name for the board, in `chief-names.json`: the same name rules as a project's name. With no name, it clears the name, and the board shows the default name "provider · folder · start time". Run it only when the user asks for it. |
| `projects rebuild --accept-listing yes` | The owner's act, so it names no chief, also on a shared logbook. Writes the known project list of this project's logbook root again: each folder of that root with tasks.tsv or ledger.tsv (`how` is `rebuild`), and prints each one. Run it only when the user asks for it, and show the user the listing: a folder that no project uses may be forged, so the user removes it and runs the rebuild again. A `projects.tsv` that is a folder refuses; a link is replaced by a regular file. |
