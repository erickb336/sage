# The PR script

Each row gives a command of the sage state tool and its full rules. Run each as the sage skill says: node, the state tool's absolute path and the command, without quotes.

| Command | Does |
| --- | --- |
| `node ${CLAUDE_SKILL_DIR}/sage-pr.mjs import\|create\|view\|merge <T>` | The PR script (not yet in the route): it imports the task's bundle for review, pushes the task's reviewed commit and opens, shows or merges its pull request, so that agents never push or call gh. It takes exactly a verb and a task id, and refuses any other word. `import` runs after the build and before the reviews: it reads the bundle as `create` does (the same checks, the same fetch with fsck into `refs/sage/<T>` of the mirror) and writes a review copy that agents cannot write, in the logbook folder: `review/<T>-<full sha>/` (the files of the bundle's tip, by `git archive`) and `review/<T>-<full sha>.diff` (`git diff` from the merge base with main). The mirror's own attributes override the commit's `.gitattributes`, so `export-ignore`, `export-subst`, `-diff` and line-end or encoding conversions hide or change nothing in the copy. It writes both in its own folder and moves them in, the diff last; it prints `imported <sha>: review the files in <folder> and the change in <file>`. An import of a tip that has a review copy prints the same line and changes nothing. The reviewers read only the review copy: `git diff`, `show` and `log` in the agent's clone do not check the objects' hashes, so an agent can make them show other text at the same SHA. `create` and `merge` refuse a reviewed head whose review copy is missing or not older than the first verdict on that SHA in the ledger (the ledger holds times to the second, so a verdict in the same second refuses too): `<sha> has no review copy from before its first verdict ...: run sage-pr import <T>, have the reviewers read the review copy that it names, and record their verdicts again`. The branch comes from tasks.tsv and the reviewed head from the task's latest verdict with a SHA; the repository from the GitHub origin of the project's main checkout (`$SAGE_PROJECT`, else the current folder). That folder must be the one that the logbook's `checkout.txt` names (the logbook key is short, so another folder can have the same one), and not in the worktree root. An origin that is not exactly `https://github.com/<owner>/<name>`, `ssh://git@github.com/<owner>/<name>` or `git@github.com:<owner>/<name>` (each with an optional `.git` and `/`) refuses: a user or token, a port, a `#`, a `?`, another host and an upper-case host do not pass, and `$SAGE_REPO` must be unset or name the origin's repository. The branch must be a task branch of that task (`[<prefix>/]t12[-<words>]`, the same rule as `task set branch=`), never main. `create` reads `<worktree root>/<logbook folder>/<T>.bundle` (`git bundle create <file> main..<branch>`) once, not through a link, a plain file with one link and at most 10 MiB that starts with `# v2 git bundle` or `# v3 git bundle`, and copies it; it fetches the copy into its mirror (`mirror.git` in the logbook), with fsck and without tags. git always names the mirror with `--git-dir`, so it never uses a repository in a folder above it; a new mirror is made in the script's folder and moved in whole, and a `mirror.git` that is not a bare repository (a file, a link, an empty or other folder) refuses: `<mirror> is not a bare git repository: ask the user to remove it`. It refuses a bundle tip that is not the reviewed head and a head that is already on main, pushes fast-forward only and never a tag, and opens a pull request only when the repository itself has none open from the branch into main (a fork's pull request does not count, by `isCrossRepository` only, so a renamed owner still finds its own; GitHub allows one open). It reads at most 100 pull requests of the branch into main (`--limit=100`, forks' pull requests with the same branch name count too) and refuses when the list is full, because the task's own can be missing, so a second `create` after a repair only pushes. When a pull request of the branch into main is already merged, also when the logbook has no PR number, `create` refuses (`already merged as PR #<n>: nothing to create`), because after a squash merge the head is not on main. It records the open pull request's number with `task <T> set pr=<n>` when the task has none or another one (such as a closed one, or one that GitHub does not have), and says so. `view` prints the pull request. `merge` takes the task's PR number from the logbook (digits with no leading zero: the state tool's own rule for `pr=`), checks that it is a pull request of the branch into main in the repository itself (else it names `sage-pr create`), that it is open, that the task is `verified` or `pr-ready` (else `sage task <T> set state=verified`) and that GitHub has the reviewed head (else it names `sage-pr create`, which pushes a repair), runs `merge-check` on the reviewed head with that PR, and merges it with `--squash --delete-branch --match-head-commit <head>`. Then it reads the pull request again: only MERGED at the reviewed head counts, so a merge queue that leaves it open is exit 2, and a gh error after GitHub merged (such as a branch deletion that gets 403) is still a merge. Then it fetches the new main into the mirror. When that pull request is already merged with the reviewed head as its head, `merge` prints `already merged: <branch> at <sha>; nothing to do`, refreshes the mirror and exits 0; when GitHub merged another head (a web merge, or a merge before a repair), `merge` and `create` refuse: `pull request #<n> merged <sha>, not the reviewed head <sha>: ask the user`. git and gh run without a shell; gh runs in an empty folder with `--repo` and `--` before the branch or number, with `GIT_DIR` naming no repository and `GIT_CEILING_DIRECTORIES` at the script's folder. The script's own files are in a new folder in the logbook folder, which agents cannot write; it writes and runs nothing in the temp folder, and refuses a bundle whose folder is a link: it goes into the folder, checks where it is, and opens the bundle relative to it. The whole call holds the logbook's lock (`withLock`), so two calls on one project never share the mirror; at the start it removes the folders of earlier calls, and each time it uses the mirror (import, create and the refresh after a merge), after the mirror check, it removes the mirror's old `FETCH_HEAD`. A folder that it cannot remove gives a warning on stderr and keeps the exit code. A lock or disk error of git on the bundle fetch or an ancestor check is a failure (exit 2), not a refusal. Only git's own result refuses: `fatal: not a git repository` (exit 128) for the mirror, and exit 1 with `unrecognized header`, `Repository lacks these prerequisite commits` or another of git's bundle errors for the bundle; any other failure of git is exit 2, `run sage-pr again`. Each git call on the bundle's objects (verify, list-heads, the fetch, merge-base, archive, diff) and tar stops after 120 s (`SAGE_PR_TIMEOUT` sets 1 to 9999 s, for a test or a slow disk) with exit 2, so a small bundle that expands to gigabytes never holds the lock for long; calls to the origin have no limit. git and gh get only these variables of the environment: `PATH`, `HOME`, `LANG`, `LC_*`, `GH_TOKEN`, `GITHUB_TOKEN`, `GH_CONFIG_DIR`, `SSH_AUTH_SOCK`, sage's own (`SAGE_*`, `CLAUDE_CONFIG_DIR`), and `NODE_TEST_CONTEXT` and `TMPDIR` (for the lock's test probe; git and gh get the script's folder as `TMPDIR`); git reads no system or global config and no credential helper from a config file, and gets github.com's credentials from gh's login (`gh auth git-credential`). The mirror keeps no `FETCH_HEAD`. The script refuses to run with `NODE_OPTIONS` set (`env -u NODE_OPTIONS node sage-pr.mjs <verb> <task>`). No message prints the origin, `$SAGE_REPO`, a URL's user or password (also with punctuation, or with no path after the host), an `Authorization` header (also quoted or as key=value), the value of `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` or `GITHUB_ENTERPRISE_TOKEN`, or the arguments of a failed git call. Each refusal names the next step. Exit codes: 0 done (also already merged with the reviewed head), 1 refused (the script's own checks, or git's own result that the mirror or the bundle is not one), 2 failed (a git or gh call failed or took too long, such as the network, GitHub, a merge that GitHub refused or only queued, or a lock or disk error; or the logbook stayed busy), 3 merged but the mirror refresh failed (the merge happened: run `merge` again later; it says "already merged" and refreshes the mirror). |
