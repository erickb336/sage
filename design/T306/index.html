How a command finds its logbook

  1. A row for this checkout: use the shared logbook.
  2. No row, and an old logbook: use the old logbook. The project waits for its move.
  3. No row, no old logbook, and the same first commit as a bound project: refuse. The chief asks the owner to link it or to start a separate project.
  4. None of these: make a new shared logbook.

Ownership rules

Claim → work → offer → runs finish → recipient accepts. The owning chief stays while a transfer waits. A run that ends does not advance the transfer.

Design ruleWhat the owner sees
1. One owning chief per taskA claim wins only on the current task version. A new task belongs to the chief who added it. A competing claim names the owning chief and changes nothing.
2. A transfer has no gapThe sender can cancel. A cancelled offer cannot be accepted, even after a new offer to the same chief. Reports stay available.
3. One guard for every writeTask writes need the owning chief. Any chief may open a Replace gate. Gate answers use the owner’s own words from either provider. A stop hook writes only its own run. The guard prevents mistakes; it does not stop a hostile agent.
4. The next writer finishes a saved changeAny writer of the project finishes a saved change first, from the request saved in it. That gives the writer no authority on the task. A saved change that cannot finish stops only that project.
5. Keep evidence separateA late report stays with its run and backs no verdict. A moved task keeps no verdict and no kept report, so it gets fresh reviews.

Owner decisions in this design

Recovery

Unknown keeps ownership. Neither provider reports a chief’s end today. So a chief that stops shows as unknown, and the way forward is a Replace gate.

A normal restart or resume keeps the same chief.

Transfer

One chief; the recipient accepts. The owning chief stays while runs finish and the recipient decides.

Late reports stay separate for the new chief to check.

Project boundary

Linked worktrees share one logbook. A move, a copy and a clone follow one rule: no row, refuse, explicit link.

No cross-machine sync.

Moving a project

Open tasks move with new numbers. New numbers start above the highest number in both old logbooks.

Finished tasks stay read-only, with a label on the board. The move needs both plugins updated and zero running runs.

A saved change that cannot finish stops writes and merges in its own project only. Existing findings, verdicts and merge checks still apply.
