- **Proof by run for findings, in Claude and Codex (T947).** A medium or high finding of a review or QA carries its proof, on indented lines under it: `proof:` with one command and `saw:` with the output line that shows the problem, or `proof: screenshot <path>` and `steps:`. A low finding needs no proof.
  - The stop gate of each provider stops a review or QA agent once when a medium or high finding has no proof, or when its command runs a process program, a git stash, inline code (`node -e`, `sh -c`), a write outside the scratch folder, or git other than status, log, show, diff, rev-parse, ls-files, grep, cat-file or blame (also any `git -C`, `-c`, `--git-dir`, `--work-tree` or `--output`) (core's `proofProblem`). One pair of backticks around a `proof:` or `saw:` value is a mark, not part of the command. The second stop goes through.
  - Before any verdict and any `round` of a cycle with such a finding, one QA run, the proof check, reruns each proof on a detached worktree of the head, after the project's dependency install (for example `npm ci --ignore-scripts`). It refuses a proof that writes, as `could not run`. Its EVIDENCE gives each finding `reproduced`, `not reproduced` or `could not run`, also on the EVIDENCE line itself and in near forms (a colon after the key, a bold key, a numbered list, a note after the outcome). Its report backs no verdict.
  - `finding triage <T> <K> fix|dismiss --proof R<n>` names the proof check. The state tool checks that it is a done qa run of the task, whose kept report lists the key, on the head that the kept report of the finding's run names. `not reproduced` backs only a dismissal, with the reason "not reproduced in R<n>"; `reproduced` and `could not run` back only a fix. A decision row keeps the run, the outcome and the head. The Codex `finding_triage` tool takes `proof`.
  - Core's lead policy, for both providers: in reviewing or verifying, a lead's fix triage of a medium or high finding needs `--proof`; a lead drops a medium finding only with `--proof`; a high finding stays the chief's, also when it did not reproduce.
  - A run whose medium findings were all dropped backs its clean verdict, as after any dismissal.
- **Limits.** The scratch homes of the proof check (HOME, SAGE_HOME and the home setting of each agent tool) are a rule of the text only. The stop gate reads a proof as written: a disguised form, such as a variable or text piped into a shell, is a documented limit. A real problem that no command can show yet can be dropped; the drop is in the decision trail, and the chief can open the finding again.
