- **In Codex, "autopilot on" works after a normal install, and a pull request lands the same way as in Claude Code.** Send `sage mode`, then `autopilot on`, each alone; nothing else is needed. The chief lands a verified pull request with `gh pr merge <n> --squash --delete-branch --match-head-commit <sha>`, and the sage gate allows it only with autopilot on and a passing merge check. The gate reads the mode from its own record of your typed phrases, with the session that Codex gives it, so a mode file or a session id that an agent makes does not count. Before, the skill sent the chief to a separate merge helper that needed evidence files that a chief could not make, so autopilot stayed off; that helper is gone. The gate now also refuses a message from any thread to the session's main thread, in any namespace of the multi-agent tools, because Codex counts it as your own typed message. In sage mode it refuses multi-agent v1's `send_input`. In every mode, no thread runs `codex` from the shell except `codex --version` and `codex --help`, because a queued message (`codex queue`), a resumed or a forked session gives Codex a prompt that it records as your typed message. It runs only the `gh` commands that sage uses, such as `gh pr view`, because an alias (also of two words), an extension, or a changed pager, editor, browser or `HOME` could run any gh command, also a merge ([guide](docs/guide/codex.md#the-rules-in-codex)) (T534).
