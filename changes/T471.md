- **Harder Codex rules.** The Codex hook now also blocks these ways around a sage rule:
  - a role agent's message to another thread: `send_input` (multi-agent v1), and `send_message` and `followup_task` (multi-agent v2, in the default `collaboration` namespace), because a message to the chief's thread would count as typed by you, and a reviewer's message could make the implementer change the branch. The chief, and agents without a `sage_` name, send as usual;
  - an agent's `logbook repair` and `standing add` from the shell, which write the logbook;
  - a name of the sage folder or of a `.codex` folder behind quotes (`.co""dex`), `~`, `$HOME` or `$CODEX_HOME`, or from the folder that the command runs in.
  - Not blocked, and written in the guide's limits list: a role agent's start of Codex through text or a script piped into a shell or an interpreter, through a copy of codex (made in the same command or an earlier one), through a link to codex made in the same command, or through text that hides the word codex; and an agent's run of the state tool's write commands from `node -e`, `node -` (standard input), after a `node` option, as a module to load, or from a copied script. Codex's sandbox is the stop: in workspace-write, network access is off for the session, and the Codex home and the logbook are read-only.
  - A `node` script whose name only has the state tool's name in it (`node src/message.mjs`), or that gets the tool's path as data (`node scripts/lint.mjs <tool>`), runs again for every agent. So do normal commands that name codex, such as `~/bin/tool codex`, `pushd packages/sage-codex && ../../node_modules/.bin/esbuild …` and `cat codex.json | python3 -mjson.tool`.
  - The brief tool's message now names each field form that the check takes: a colon, two spaces or a tab after the name, or the name alone on its line.
  - The brief check now starts a field only at a line that is the field's name with a colon (`FORBIDDEN:`), two spaces or a tab after it, or nothing, outside a list or a code block. So a line such as "FORBIDDEN words are flagged" in another field no longer gives a role agent the wrong `FORBIDDEN` text.
  - The chief's setup text in Codex now says that the state CLI only reads (`board`, `config`), and that `program` has no tool yet, so programs do not run in Codex. The limits that stay are in [sage in Codex](docs/guide/codex.md#the-rules-in-codex).
