- **In sage mode the chief writes and removes its own scratch files and pages, in Claude Code and in Codex, with one core rule (T807).**
  - The owner decided this on 2026-11-07 (T668 Q4). Since T960 the chief's shell writes were refused everywhere outside a redirection into the temp folder, so the chief could not remove the empty folders that an agent had left in `~/sage-worktrees`.
  - The chief's scratch places come from code (core's `chiefPlaces`): the temp folder and the sage worktrees folder (`~/sage-worktrees`, or `$SAGE_WORKTREES`), which holds each project's pages folder (the folder that the state tool's `pages` command prints).
  - There a redirection, a heredoc, `rm`, `rmdir`, `touch`, `tee`, `cp`, `mv` and a gh clone or download run, with literal paths. A leading `~` counts as the home folder. A link counts both by its own path and by the place that it leads to, so `rm` of a link in the project stays refused.
  - A write into the project, into `~/.claude`, into the sage worktrees folder itself or the temp folder itself, or into any other folder stays refused. So do `sed -i`, code in `node -e` and the other write forms, also in the scratch places. The logbook's own rule still refuses a write into the logbook, also when the logbook is in the temp folder.
  - A git work tree in the sage worktrees folder (a task worktree or a clone) holds repository files. A write into it, also from it as the command's folder, and `rm -rf` of a folder that holds one stay refused, with a text that names `git worktree remove <path>` without `--force`: git refuses to remove a worktree with changes (F-T807-1).
  - The chief's git that throws away uncommitted work still runs only in a scratch worktree in the temp folder (T968). `git worktree remove --force` counts as such git now.
  - Chains of state tool commands (`node <sage.mjs> status ; node <sage.mjs> board`) run: the hook does not refuse them, and a test now proves it in both providers.

| Command of the chief, in sage mode | Decision | Reason |
| --- | --- | --- |
| `rmdir ~/sage-worktrees/<folder>`, `rm -rf ~/sage-worktrees/<leftover folder>` that holds no git work tree | Runs | The chief cleans up what its runs left (T807). |
| `git worktree remove ~/sage-worktrees/<worktree>` | Runs | git refuses a worktree with changes, so no work is lost. |
| `rm -rf` of a git work tree in `~/sage-worktrees` or of a folder that holds one, a write into one (also from it as the command's folder), `git worktree remove --force` | Refused | A work tree holds repository files and maybe uncommitted work (F-T807-1). |
| `cat > <pages folder>/T1/plan.md <<'EOF'`, `tee`, `cp` or `touch` into the pages folder | Runs | The chief saves its own research pages and notes (T668 Q4). |
| `rm -rf /tmp/<run>`, `mv` and `cp` inside the temp folder, `cp src/a.js /tmp/<run>/a.js` | Runs | Scratch work. `cp` changes only its destination, so its source may be in the project. |
| `rm`, `rmdir`, `touch`, `tee`, `cp` or `mv` with a target in the project | Refused | Repository files stay with an implementer. `mv` also removes its source, so a source in the project counts. |
| A write into `~/.claude`, into another folder of the home folder, or `rm -rf` of the temp folder or the sage worktrees folder itself | Refused | Only the folders inside the scratch places count. |
| A write into the logbook | Refused | The logbook rule, as before. |
| `xargs rm`, `env rm`, `cp -t <dir>`, `touch -d <date>`, a variable or a pattern in the path (`rm $TMPDIR/x`, `rm /tmp/x/*`), `~user/` | Refused | The hook cannot name every target of these forms, so it fails closed. Write the literal paths. |
| `sed -i`, `node -e`, `dd`, `install`, `rsync`, `tar`, `ln` into a scratch place | Refused, as before | Each has its own write grammar; the observed need is the forms above. |
| `node <sage.mjs> A ; node <sage.mjs> B` | Runs, unchanged | The hook already lets a plain chain of state tool commands run. A write in a shared logbook still names `--chief`; the state tool refuses it without one. |
