- **The move's recovery paths and edge cases (T647), before any real move.** Fixes from the reviews of the move (T640).
  - A move gate moves once. After a restore by hand, its answer moves nothing: the move wrote a row in the gate's logbook, and the restored folder keeps the plan in its name. The owner answers a new preview and gate.
  - The restore steps end with a seventh step: rename the plan `moves/<folder>.json` to `<folder>.json.aside` when it is there, so that a project with an end check that did not match is not blocked after a restore.
  - The move writes the highest new number of its map into each old logbook's decisions, so after a restore no new task, gate or program takes a number of the map.
  - The end check splits the standing orders only at the headings that the move writes, so an owner's own heading that starts with "## From the " no longer fails a move.
  - A program moves whole: its finished tasks, also a merged pilot, move with it as finished tasks with new numbers, so its pilot, its breakdown approval and its done count stay. The move no longer refuses a program whose pilot merged.
  - A round key whose finding closed before the move moves as a new key with no row, so the task's next round counts as before the move and does not go to replan.
  - A chain of adoptions gives each old row the number of the task that moves at its end; a loop of adoptions refuses.
  - A command that found an old logbook and waited on its lock refuses while a move plan names that logbook, so a stop between the marks of two old logbooks still finishes with the same command.
