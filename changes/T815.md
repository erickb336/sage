- **The hooks judge the programs that a command line runs, not its text (T815, part 1: core and the Claude hook).** By the owner's decision of 2026-11-07, the shell-text rules are gone; they caused most agent refusals, nearly all of them false alarms. On the refusals that agents met since 2026-11-07 22:00, 327 of 346 (95%) now pass, and each one that stays refused meets a rule that the cut keeps.
  - A merge is a run of `gh pr merge`, or of `gh api`, `curl` or `wget` with a pull request's merge path, a repository's merges path or a GraphQL merge mutation, also inside `sh -c`, `eval`, `xargs`, `find -exec`, `env` or `$( )`, and behind a wrapper that the hook does not know, such as `arch -arm64`, `op run --` or `script -q /dev/null`; a doubled slash in the path counts as one. An agent's gh and state tool rules read gh and node behind such a wrapper too. Merge or push text in a commit message, a pull request body, an echo or a tool call's description passes.
  - An option before or between gh's first two command words is refused, other than `-R` or `--repo` and its value: gh lets an option take the next word as its value, so `gh pr -b view merge 12` runs `gh pr merge`. The refusal names the option and the plain form.
  - A `git push` that another program runs is refused: a push runs only as a command of its own, in the push form. The merge form, the merge check, the push form, the owner's push rule, the known git subcommands and the hooks path and `.git` rules are unchanged.
  - An agent's or the chief's shell write is refused when a literal path of a written word, a `key=value` or `--option=value` value, or a redirection target is in the sage root or the shared root, also through a link, after a `cd`, `pushd` or `popd`, or from `~`. A pattern counts by its literal part. A remove, a move or a recursive lock of a folder that holds a root (`rm -rf ~/.claude`, `mv ~/.claude ~/.claude.bak`, `rm -rf ~/*`, `find ~ -delete`, `chmod -R`) is refused too. A logbook file's name elsewhere, `$?`, braces and scratch work pass; the scratch exemption is gone with the rule that it eased.
  - A refusal names the word that caused it: a long word shows its start and its end, so the root part stays visible, and the expansion refusal names its word. When the hook cannot read a line, each refusal leads with the cause and the way forward, in the same words for every rule; such a line is still refused when its words run a `gh api` write of main or the default branch, `gh repo sync`, `gh repo edit --default-branch` or a git subcommand that the hook does not know. The hook now reads a literal `cd ~` and `cd ~/<path>` as the home folder. `command -v` and `command -V` run nothing, so the fake-proof step of standing order 57 passes, and an agent's `gh api -iX DELETE` reads as a DELETE.
  - An agent runs the state tool's read commands also in a pipe or a chain, and any program may read its files. It runs `gh pr create`, `view`, `comment`, `edit`, `checks`, `diff`, `list` and `status`, `gh issue view` and `list`, `gh run view`, `list` and `watch`, `gh repo view`, and `gh api` with GET, by gh's own words, with any command before or after them.
  - The owner check of `sage-pr create` and `merge` from T901 stays: it runs first and refuses when it cannot finish. Its text rule goes with the cut (F-T901-7): the hook judges the PR script's runs, so an echo or a search that names the script passes. A line that the reader cannot read is refused when its text names the script and `create` or `merge`.
  - A variable or a substitution in a program word or a path, a pattern in a path or a plain argument after its literal part (a pattern in a program word or in git's or gh's command words is refused), a gh alias or a renamed copy, code or a script, text piped into a shell, and a folder known only at run time are documented limits of the hook; the sandbox is the full guard ([Rules held in code](docs/design/rules-in-code.md#the-limits-of-the-hook)). The Codex gate takes the shared merge rule and push readers now; its own shell-text rules go in part 2 (T903).
