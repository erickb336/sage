- **A project can start every session in sage mode, in Claude Code and in Codex, and the Codex chief changes no file from the shell (T948).**
  - New setting: `sage config start=sage-mode` (the `config` tool in Codex) starts each new session of the project in sage mode, from any checkout. `start=normal`, the default, starts it with sage mode off. The setting is in the project's logbook, so Claude and Codex read the one setting when they share the logbook. `sage mode off` still gives a normal session for the rest of the session. See [Start every session in sage mode](docs/guide/using-sage.md#start-every-session-in-sage-mode).
  - The Claude Code line `"agent": "sage:chief-of-staff"` in `.claude/settings.json` still works. The new setting is the way that works in both providers.
  - In Codex, a session that started in sage mode by the setting counts your `autopilot on` as after `sage mode`: the start note keeps the start.
  - In Codex, the gate refuses the chief's shell writes in sage mode, with the same write forms as for a reviewer: a redirection into a file, a heredoc into a file, `tee`, `cp`, `mv`, `rm`, `sed -i` and code in `node -e`. A redirection into the temp folder, outside the project, runs, and so do git, gh, the sage tools and reads.
  - Core's write forms no longer read a word after `gh` as a program, so `gh api -X PATCH` and `gh config set pager less` are no writes, also for a reviewer.
  - [Known limits in Codex](docs/guide/codex.md#known-limits-in-codex) now has 8 rows: the start in sage mode and the chief's plain shell writes are no longer limits, the row about role texts was a design note, and one row names the chief's shell write forms that the gate does not read.
