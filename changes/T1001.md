- **One link opens each page, in every app (T1001).** The Page block of a message from the chief now has three lines: `Page ·` and the title, then a link such as `http://127.0.0.1:43123/pages/sage-43265b/T1000/research.html`, then the file path on your Mac. A click on the link opens the page from the board server that already runs on your Mac: in the Claude desktop app's Browser pane, in the Codex app's built-in browser, and in your default browser from a terminal. `http://127.0.0.1:43123/pages/<logbook>/<task>/` lists all pages of a task ([the pages of a task](docs/guide/board.md#the-pages-of-a-task)).
  - The board shows web pages, PDFs, pictures, and Markdown and text as plain text, read-only, on the Mac only. Each page opens in a sandbox: it cannot read the board or your files, load anything or send a form, and only sage's own script runs (a design's switch). The message command now refuses a Page block that names a file that the board does not show.
  - Two warning lines in the task's index: a page may link to sites outside this Mac, and "Open with its scripts" (for a page with a script of its own) lets the page's own scripts run, which can send the page's own content to another site.
  - Known limits: the link always names port 43123; a board that launchd starts shows only the pages under `~/sage-worktrees`; a page can still send its own content out through a link that you click in it.
  - Your one check: after you update sage and restart the board (`board --stop`, then ask for the board), click one Page link in the Claude desktop app, in the Codex app and in a terminal. Each opens the page.
