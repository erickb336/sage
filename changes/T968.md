- **In sage mode the chief no longer runs the git forms that throw away uncommitted work in the project, in Claude Code and in Codex, with one core rule (T968).**
  - `git reset --hard`, `git checkout -- .` and `git checkout -- <path>`, `git clean -f` in any form and `git restore` of the work tree are refused for the chief in the project's main checkout. The refusal says why, and names the safe way: make a scratch worktree in the temp folder and run the command there, or ask the owner.
  - In a scratch worktree (a worktree in the temp folder, outside the project's main checkout) they run, also when that worktree is the command's folder.
  - The chief's merge steps run as before: `git merge-tree`, `git commit-tree`, `git worktree add --detach` and `git worktree remove --force` of a scratch worktree. So do `git commit`, `git checkout <branch>`, `git fetch` and reads.
  - A correction of the T936 entry: the chief's git does not all run. `git rm` and `git mv` are write forms, so they were refused since T960, and now the forms above are refused too.
  - A reviewer whose folder is its own scratch worktree runs git there (F-T936-5). In Codex, a reviewer's shell refusal names the scratch-worktree command, as in Claude Code (F-T936-3).
  - awk's comparison in parentheses (`print ($1 > 3)`) and a print into `/dev/stderr` no longer count as a write (F-T936-1).

| Command | Decision | Reason |
| --- | --- | --- |
| `git reset --hard`, `git checkout -- .`, `git checkout -- <path>`, `git checkout .`, `git checkout --force <branch>`, `git switch --discard-changes` | Refused for the chief in the project; runs in a scratch worktree | They can destroy uncommitted work in the owner's main checkout. |
| `git clean -f`, `-fd`, `-xdf`, `--force` | Refused for the chief in the project; runs in a scratch worktree | They delete files that git does not track. A dry run (`git clean -n`, `-fn`) only reads, so it runs. |
| `git restore .`, `git restore <path>`, `--worktree` | Refused for the chief in the project; runs in a scratch worktree | They overwrite changes in the work tree. `git restore --staged <path>` changes only the index, so it runs. |
| `git merge-tree`, `git commit-tree`, `git worktree add --detach`, `git worktree remove --force` | Run | The chief's merge steps. Removing a scratch worktree is allowed. |
| `git commit`, `git checkout <branch>`, `git reset` without `--hard`, `git fetch`, `git log`, `git diff` | Run | They keep the work tree's changes, or git refuses to overwrite them. |
| `git rm`, `git mv` | Refused for the chief, as since T960 | They are write forms. The T936 entry said that the chief's git runs; that was not true for these two. |
| A disguised form: a git alias, a variable, a path without `--` (`git checkout HEAD src/a.js`), `git reset --merge`, `git checkout-index -f` | Runs: a documented limit | The rule guards honest mistakes (standing orders 49 and 70). |
| A reviewer's `git checkout main` with its own scratch worktree as its folder | Runs | That folder is outside the project's main checkout (F-T936-5). |
| `awk '{ print ($1 > 3) }'`, `awk '{ print "x" > "/dev/stderr" }'` | Run | A comparison and a print to standard error write no file (F-T936-1). `print > ("out" NR)` still counts. |
