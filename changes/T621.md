- **Fewer false refusals from the hook.** Three hook rules stopped harmless work, and a real write to the logbook is still refused (T621).
  - The rule for a logbook write judges each part of a command line on its own. So `touch a && ls <logbook folder>` passes, and a pattern or a name in a command that only redirects (`jq '.items[]' a.json > /tmp/out`) passes. A part that sets a folder or a variable, or that runs an interpreter, stays judged, and a line with a substitution, a group or control flow is judged whole.
  - The hook reads the run from a brief's first line that ends with punctuation, such as `Run R7 · task T3: build`. The refusal for an agent with no run names each cause.
  - An implementer can run `gh pr create` and the other allowed `gh` commands after `cd <worktree>` and `git push`, and it can give a body as `$(cat <<'EOF' ... EOF)`. Before, only one plain `gh` command passed.
  - A blank GitHub repository has a way forward. The first push makes the task's branch the default branch, and then the push rule refused that branch. The main session can now run `gh repo edit github.com/<owner>/<repo> --default-branch main`, which asks you. The hook first checks on GitHub that main is one root commit. No agent gets this form, and no agent pushes to main.
