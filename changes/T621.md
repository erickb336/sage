- **Fewer false refusals from the hook.** Three hook rules stopped harmless work, and a real write to the logbook is still refused (T621).
  - The rule for a logbook write drops a plain reader from a Bash command line. So `touch a && ls <logbook folder>` passes, and a pattern or a name in a reader that only redirects (`jq '.items[]' a.json > /tmp/out`) passes. Every other part stays judged, also one that the hook does not know. A line with a substitution, a group, control flow, an alias, an assignment or a `>!` is judged whole, and so is every line of another tool, such as PowerShell.
  - The hook reads the run from a brief's first line that ends with punctuation, such as `Run R7 · task T3: build`. The refusal for an agent with no run names each cause.
  - An implementer can run `gh pr create` and the other allowed `gh` commands after `cd <worktree>` and `git push`, and it can give the value of `--body` or `--title` of `gh pr` as `"$(cat <<'EOF' ... EOF)"`, in double quotes. Before, only one plain `gh` command passed.
  - A blank GitHub repository has a way forward. The first push makes the task's branch the default branch, and then the push rule refused that branch. The main session can now run `gh repo edit github.com/<owner>/<repo> --default-branch main`, which asks you and shows what GitHub counts. The hook first checks on GitHub that main is one root commit, and it refuses past 20 commits on the default branch, 5 branches or 3 open pull requests. No agent gets this form, and no agent pushes to main.
