- **The chief works the same way on each kind of work (T985).** A new playbooks page in core gives nine kinds of work one playbook each: a feature, a broken behaviour or setup, a design, an architecture choice, a refactor, an investigation, an undecided case, a milestone and a new rule or guard. The chief's text has one trigger line for each, so the chief reads the playbook when a request is of that kind, in Claude and in Codex.
  - Each playbook has five parts: how the chief knows the kind, what agents prepare before you see anything, your one small choice with the recommendation first, what the logbook records after your answer, and one idea that you learn, with a real example.
  - Each choice comes in a message kind that you know, for example a question with the case table for an undecided case, or two architecture pictures side by side for an architecture choice. The message says what happens if you do not answer before it asks.
  - Where the work is easy to undo, the recommendation goes ahead with no answer, for example an internal shape that is easy to change. What changes the data that you keep, or what you see, waits for you.
  - The milestone playbook now holds the milestone steps, and the rule to seal a lesson is now in the new rule or guard playbook. `npm run check` checks that each playbook has its five parts, names a message kind and its default, and has its trigger line.
