- **A clean merge of main keeps the reviews.** When a pull request's new head only merges main into the reviewed head, and main's side is in the pull request's base commit on GitHub, the merge check now keeps that head's review and QA verdicts, so the task needs no fresh cycle. CI still runs: record `checks-pass` on the new head. The pull request's diff outside built files must be the same as the reviewed one, so a merge whose only conflict is in a built file, fixed by `npm run build`, counts too; any other change refuses and says why. A file that both sides changed refuses, also when git merges it with no conflict. Apart from the base commit, the merge check reads only git objects (no replace refs), names the earlier head, and writes the carry-over in the decision trail. A built file is one that main's `.gitattributes` marks `sage-built`; in sage, `npm run build` now writes `.gitattributes` from the files that it makes. The Claude Code hook and the Codex merge rule both use it. See [the design](docs/design/sage-mode.md#carry-over).
