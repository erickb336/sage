- **Codex autopilot: only a new turn turns it on again.** After an off phrase from a fork, a subagent's thread or a side conversation, an on phrase that joins the main thread's running turn no longer turns merges on (T823). The mode hook now saves the turn of each on phrase that it accepts, and the hook and the merge command admit a merge only when the latest on phrase that counts in Codex's record is in that turn. The parts:
  - **The on phrase that joins a turn:** an on phrase sent while Codex works, or from a turn that the app's queue started, switches nothing. The chief tells you that it did not count, and to send it as a new message while Codex is idle (press Esc first if Codex is busy).
  - **A subagent's report:** an on phrase that joins a main-thread turn that a subagent's report started counts for nothing. A record line where another agent asks for a turn now stops autopilot merges.
  - **The refusals:** the merge refusals say why the on phrase did not count and how to send one that counts. The version refusal says that a newer Codex waits until sage adds it. The refusal for a missing Codex folder on the hook's `PATH` uses plain words and gives the fix.
  - **The off line:** an off phrase in a main thread whose record sage cannot read gets a line that fits a main thread.
  - **Network:** the hook no longer claims to allow the merge's network access to `api.github.com`. With network access off, Codex can ask you once while the merge runs: approve it.
  - **The guide:** an on phrase queued with Tab in the terminal UI counts when it starts the next turn; the no-image rule has its reason and its result.
  - **After this update:** if autopilot is on in a Codex session, send `autopilot on` again as a new message before the next merge.
