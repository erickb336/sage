- **The Codex gate judges the programs that a command line runs, not its text, as the Claude hook does since T815 (T903, part 2 of the cut).** By the owner's decision of 2026-11-07, the gate's own shell-text rules are gone; a deliberate forgery by a variable, a pattern or an alias is a documented limit, and Codex's sandbox is the full guard.
  - A shell write into the Codex sage folder (the logbook and the mode files) or the shared root is refused with core's `logbookWrite`, in every mode and for every thread: the literal path of a written word, also through a link, after a `cd` and from `~`, and a remove, a move or a recursive lock of a folder that holds a root (`rm -rf ~/..`, `find <folder> -delete`, `mv <Codex home> <other>`). The refusal names the word.
  - Gone: the logbook name rule (`tasks.tsv`, `config.json` or another logbook file's name, refused anywhere outside the project in sage mode), the refusal of any shell write whose target has a variable or a pattern (`> $DEST`, `> out*`), and the `$HOME`, `$SAGE_HOME`, `$SAGE_SHARED_HOME` and `$CODEX_HOME` forms of the sage folder and config file rules. These rules now read a literal path, also from `~`.
  - In sage mode, the gh path rule reads gh's own words: gh from a variable or a substitution, and a setting before gh (`GH_PAGER`, `EDITOR`, `BROWSER`, `HOME`, `GH_CONFIG_DIR` and the like), pass as documented limits. The gh command paths that sage uses are unchanged.
  - Unchanged: the merge rule and sage's merge command, the push rule with its owning chief, the state tool rule, the owner record and the merge permit of autopilot, the `.codex` folder, `.git` folder and Codex run rules, and the read-only roles.
