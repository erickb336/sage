- **Safe ground for the move of existing logbooks (T641, PR 7a of the shared logbook).** Nothing moves yet: every command of a legacy or a shared logbook works as before.
  - A logbook with a `moved.json` marker refuses every write under its lock, with a line that says it moved and to run the command again, which then finds the shared logbook. So a writer that found the old logbook just before the move and waited on its lock writes nothing there. A read still reads it.
  - The move can write one id floor row per prefix (T, R, G and PG) in the new logbook's decisions, for example `T644 is the task floor of the move from claude and codex`. Every sage, also an older one, then gives the next number above it, so an id of an old logbook never comes back. A finding's key counts inside its task, so it needs no floor.
  - The plugin contract in `plugins.tsv` is now 2: a state tool that writes 2 refuses a moved logbook. The move can ask which providers still wait: a provider with no row, or below 2, waits; a row with `unused` does not.
  - An adoption record of version 2 reads: the PR and the branch are optional, and `from` keeps the task's own version 1 record, so an adopted task's branch and PR stay its own after the move. A version 1 record reads as before.
  - The Claude plugin names the provider of each old logbook root. A plugin that gives a bare path still works, with no provider name.
