- **Reviewers and QA can write and run their probes in their own scratch folder.** Before, the hook refused a fake script with `"$*"`, a heredoc proof with braces, `node -e` with `{spawnSync}` and `$?` as "near the logbook", also in the agent's own scratch folder. Now a run's own scratch subfolder, `<scratchpad>/<run id>`, takes these writes and runs: a heredoc, `echo` or `printf` into it, `mkdir` and `chmod` on it, `node` on a script in it, and `node -e` code whose paths are in it. Each argument of `node` is a path in the folder or a plain word, and `SAGE_HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `HOME` are set only to paths in the folder. The text of a file that a command only writes is data, also words such as `kill` or `verdict`. A script that node runs there, or a text that the same command writes, may not name the state tool, a merge or a push. The hook finds the folder from facts that the agent cannot set. When it cannot, it refuses as before, and its refusal says why: for example, the brief's first line must be `Run R<n> · task T<n>`, and text may follow after a space. A refusal also names the run's folder and why the command did not qualify. A command that writes to a path outside the folder, reads the logbook, uses a link, or uses `..` goes to the usual rules. As before, a bare file name in `node -e` code still writes in the working folder.
