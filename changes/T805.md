- **A clean merge of main keeps a pull request's clean cycles (T805).** Before, a merge of main into the branch (or GitHub's update branch) made a new head, and the merge check wanted every cycle again, although the pull request's own change did not move.
  - The merge check counts the clean cycles of an earlier head H1 for the new head H2 only when each commit from H1 to H2 merges a commit of `origin/main` with no conflict and no other edit, the pull request's own diff has the same `git patch-id --stable`, checks-pass is on H2, and H2 has no review or QA verdict of its own.
  - Its line names both heads: `cycles from <H1> carried to <H2>: clean merge of main, same patch-id`. A refusal says why the cycles did not carry. Any git error refuses.
