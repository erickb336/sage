- **In sage mode, no push reaches the default branch, whatever the remote's name.** The push rule of the Claude hook and the Codex gate (one rule in core) reads the checkout's remotes and git's settings, and asks GitHub for the repository's default branch with a GET; when GitHub does not answer, the push is refused. A push to a remote with any name passes for the task's branch, so a project whose one remote is `github` works. A push to main, master or the default branch is refused in every form: `HEAD:main`, `:main`, `refs/heads/main`, `--all`, `--mirror`, a URL, `-C`, `git -c`, a symbolic branch ref, and the settings `remote.<name>.push`, `remote.<name>.mirror`, `url.<base>.insteadOf` and `push.default` upstream. Beside the push, a line may only run `cd`, `pwd`, `git add`, `commit`, `status`, `log`, `diff`, `show`, `fetch` or `rev-parse`, `gh`, `echo`, `printf`, `true`, `cat`, `head`, `tail`, `grep` or `wc`, and writes no file (`tee` or `>` is refused) and sets no upstream (`--set-upstream`, fetch's `-u`). `git subtree push`, a git subcommand that is not a known built-in (`send-pack`, an alias), a setting of `core.hooksPath` or `core.fsmonitor`, a write under `.git`, `gh repo sync`, `gh repo edit --default-branch` and a `gh api` write of `default_branch` are refused too. These text rules cannot be complete; GitHub branch protection is the real lock.
