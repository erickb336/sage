- **Two tasks can share one pull request under autopilot.** The chief can now give a second task the branch of another task (`task <T> set branch=<the other task's branch>`), with the same `pr=`. Autopilot merges that pull request when each task passes on its own verdicts. Before, the merge check refused it, because its head branch was not named for each task, so you merged it yourself. The merge check still refuses when a task of that branch is not on the pull request, or when one task of the pull request names another branch. A lead still names only a branch of its own task, and only the chief puts a task on a shared branch or takes it off one, also a branch named for the lead's task when another task names it or ran work on it. A task that ran work on a branch stays an owner of it after it moves to another branch, so it must be on that pull request too. The PR script's merge runs the same head branch check as the hook. When a task that owns the head branch is not on the pull request, the refusal says how it owns the branch (by its name, by a run on it, or by its `branch=`), and it says to move the task to another branch only when that works: when it owns the branch by its `branch=` alone.
