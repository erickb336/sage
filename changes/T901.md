- **The owner check of `sage-pr create` and `merge` fails closed in a shared logbook, and a legacy push reads no logbook (T901).** Repairs of the push rule of T822:
  - In a shared logbook, the Claude hook checks that the session's chief owns the task before it reads the task's branch. When the hook cannot read the logbook (a damaged table such as an empty `chiefs.tsv` or `findings.tsv`, an event with no session id, or a busy lock), `sage-pr create` and `merge` refuse and name the cause. Before, another chief's `create` or `merge` then passed.
  - The hook reads `sage-pr create` and `merge` after `SAGE_PROJECT=<folder>` and `env -u NODE_OPTIONS`, the forms that the script's own refusals name, and checks the logbook of that folder. A line that runs `create` or `merge` in another form, such as after `cd` or in a chain, refuses and names the plain form.
  - In a legacy logbook, the hook reads no table for `sage-pr create` and `merge`, and a `git push` reads no logbook in either hook (Claude or Codex). So a damaged table no longer refuses a push that worked before T822.
