- **A saved change that cannot finish now has a way out with no backup.** When you accept the loss, the chief runs `sage logbook repair --accept-change-loss yes`. The repair records a decision, keeps the stuck file as `review-pending.json.lost-<n>`, and the project saves again. It refuses, and changes nothing, on a logbook with no saved change, on a change that can finish, on a change that may finish from the real folder of a logbook behind a link or on a newer sage, and on a damaged task-update receipt, which needs a backup. It does not repair the tables, and it says so: a half-published update can leave mixed tables, and tables that are each whole but do not agree pass the logbook check. Sage still never drops a saved change by itself; this step needs your answer each time. In Codex, no tool runs the repair, so you run it in a terminal (T593).
