- **The worktree clean-up keeps more work safe (T937).** `sage worktrees prune --yes` changes in four ways ([Clean up worktrees](docs/guide/using-sage.md#clean-up-worktrees)):
  - A clean worktree of a concluded task goes, like one of a merged task. Its reason is `concluded`.
  - A branch that no task names and that adds no commit to origin/main, for example one at its tip, reads `unknown`, not `branch merged`, and stays: a new run may have just started on it.
  - An ignored file, such as `.env`, keeps a worktree, and the reason names the file, because git deletes ignored files with the worktree. An ignored folder such as `node_modules/` does not keep it.
  - An open task's reason now says why it stays, for example "open: T4 is building, so its work may still need this folder".
