- **Codex: the gate holds the brief check and the lead run check before a spawn (T950).** Two rows leave [Known limits in Codex](docs/guide/codex.md#known-limits-in-codex): a spawn with a missing brief field no longer starts with a warning only, and a lead with no running lead run no longer starts and stops at its first write.
  - A spawn whose task name starts with `sage_` starts only when the `brief` tool checked that exact task name, with its run id, in the last 30 minutes. This holds for the chief's spawn in sage mode and for a lead's spawn in every mode. Otherwise the gate refuses it with one line, for example: "sage: sage_implementer_t12_r40 does not start, because no brief for it was checked in the last 30 minutes. Run the sage tool brief with this task name and the whole brief until it says checked, then spawn the agent again."
  - The chief's spawn of a lead (`sage_lead_t<n>_r<k>`) starts only while that lead run runs and its task can move. Otherwise the gate refuses it with one line that says to add the lead run with `run_add`.
  - A spawn whose task name does not start with `sage_` is not judged.
  - Why the spawn can be judged: Codex encrypts only the spawn message. The task name is plain text.
  - The mark of a check is in the brief's own record in the logbook (`briefs/<task name>.json`): the `brief` tool adds the time of the check when no field is missing. A later check with a missing field removes it. The record is already keyed by the task name, which holds the run id, and the start note already reads it, so a second file would keep the same fact twice.
  - The mark counts for 30 minutes, not for one spawn. Codex can refuse a spawn after the gate passed it (its thread limit), and the chief's and the lead's steps then spawn again with the same task name: a mark used once would refuse that retry. 30 minutes covers a fix of the brief and a short wait for a free thread. After a longer wait, the refusal says to run `brief` again, which costs one tool call.
  - A mark that an agent forges, for example from a script, is a documented limit (standing order 70). The gate refuses a plain shell write into the logbook.
  - The Codex chief's instructions now say to run `brief` before each spawn of its own, not only before a lead's.
