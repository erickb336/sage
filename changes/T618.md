- **Hand a task to another chief on a shared logbook.** One chief can hand a task to another chief or give it up. With your answer, a chief can take over from a chief that stopped (T618). The [usage guide](docs/guide/using-sage.md#shared-logbooks) has the table.
  - `offer` names one other chief. The owning chief stays until that chief runs `accept`, with the exact offer, the current version and no active or unknown run. `cancel` clears the offer, and a cancelled offer never becomes valid.
  - `release` clears the owning chief, so any chief can `claim` the task.
  - `gate replace` opens a gate for you. Your answer replace sets the chief, clears an open offer and ends each run that the gate names as failed, in one saved change. The next write of any chief finishes it after a stop. This is also the way out for a Claude session after `/clear`, which is a new chief.
  - The gate's question names the title, both chiefs with their providers and each run with its role, and it says what each answer does. Only your answer counts: this rule is an instruction, not a check.
  - A replaced chief gets a refusal that names the new owning chief, also for `sage-pr create` and `sage-pr merge`, for `gh pr merge` in Claude and in Codex, and for a Codex review that it accepts. A run that ends does not advance a transfer, and a transfer changes no run.
  - A run that ended as blocked or failed keeps a late report once, with its arrival time. `task <T>` prints its path, and that report backs no verdict.
  - A Codex chief has the tools `offer`, `cancel`, `accept`, `release` and `gate_replace`, with the same rules.
  - An existing project shows no change: only a shared logbook has these commands, the `offer` column and the gate `kind` column.
