- **A Claude lead with no usage in its notice, and a count that stays (T969).** A lead that ends with a report (`done`, `blocked` or `question`) but whose notice has no usage, for example after a restart, could end only as `failed`. Now the chief ends it with its status and `--usage unavailable`, with `--usage-source`, `--usage-evidence` (the reason) and `--report`, as a Codex run does. A lead with no report still ends as `failed`, and a review run still needs its tokens. The commands reference and the chief's steps name the lead's `--tokens` rule and this way out.
  - At a later stop of the same Codex agent, a record that gives no count (for example a half-written last line) no longer replaces the count of an earlier stop with "unavailable". A new count still replaces the old one.
  - The Codex skill's limits line no longer says that a run has no token count (fixed by T956).
- **The test guard, and a correction of T944.** The T944 entry said that a test run from your checkout cannot reach your real `~/.sage`. That claimed too much: the guard covered only `os.homedir()` in the test's own process, and only for the home that the test started with. Now the guard also refuses the account's home from the system (for example after a test deletes HOME), and each `child_process` call of a test or of sage code whose env has no HOME. A child whose env has no HOME gets the account's home.
- **Limits of the test guard.** These forms pass it. Each needs code that works against the test on purpose, or a path known only at run time (order 70):
  - A child that inherits the real HOME, or gets it in its env, is not refused. Its code reads that HOME, so a test keeps SAGE_HOME and HOME in scratch (orders 53 and 54).
  - The guard does not run inside a child process, so a child's own `os.homedir()` is not guarded.
  - Code that reads the account's home without `os.homedir()` (for example `os.userInfo().homedir`, or `/etc/passwd`) is not refused.
  - A caller under any `node_modules` folder passes, also sage code that a test copies under one: the guard leaves out those folders for Playwright's browser cache.
  - Code that keeps a reference to `os.homedir` or a `child_process` function before the guard runs (a module that loads before `test-env.mjs`) is not refused.
