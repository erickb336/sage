- **The board and the link prompt: copy, layout and hardening follow-ups of the shared logbook (T631).** The [board guide](docs/guide/board.md#a-shared-project-on-the-board) and [Using sage](docs/guide/using-sage.md) have the lines.
  - The gone note under a shared task's runs names only the folder that stops the next review (the folder of the branch's newest implementer, designer or arena judge run), with its run: `The folder lantern of R455 is not on this Mac now`. Any other gone folder is faint.
  - A long checkout folder name wraps in its cell and stays in the card, and `· gone` stays whole. A "may have stopped" agent chip wraps as one line of text.
  - A Replace gate recommends `replace, when you know that <chief> stopped`. A shared run with no chief stands in as `Unknown`, not `Shared`. A finished program of an old logbook says `Old Claude` or `Old Codex`.
  - A project name and the picker's folder line show no control, bidi or line separator character, and the picker counts a linked checkout as gone by the same rule as a run.
  - The link prompt: its last line starts with "For the chief:", it names the folder that has no GitHub remote, a remote URL with a user name or a token in it reads as its repository (the token never shows), it says the board label of a folder name that another checkout has (`lantern #2`), and it prints a line or paragraph separator in a path as an escape. The message after a link says that label too.
  - A shallow clone of a project with a shared logbook gets a prompt (fetch the full history, or start separate), not a legacy logbook without a question.
  - When the first checkout of a shared logbook is gone, its oldest live clone owns the logbook: a foreign row that was linked before the clone does not take it.
  - The task lookup of the `sage-board` command finds the shared project from a linked second clone, also one with the same folder name.
