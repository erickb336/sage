- **A lead's foreground helpers keep their reports.** The lead's Agent tool can return only when the helper ends, so the call's result comes after the helper's stop. The hook now joins a lead's helper to its run at the helper's start, when its call is the only pending one of its role in the session. So the report is kept at the stop, the lead's verdict with that run passes, and the helper has its scratch folder during its work. Two pending calls of one role stay unjoined, because no start event names its call: each such run keeps no report, and it ends as failed. A brief's first line, `Run R<n> · task T<n>`, now also gives a helper's run. It must name the lead's own task, and it must agree with a name that is a run id. The other lead rules did not change. An Agent call that fails after its helper started now frees the slot, and the run may get a new helper.
