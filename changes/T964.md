- **Quoted output and a negated severity word no longer make a report unreadable (T964).** Under FINDINGS, a span in backticks or double quotes, such as a failing test name in a `saw:` line, and a severity word right after not or no (`not a blocker.`) are text. So the quoted test name of R3062 and the line of R2942 no longer cost a review or QA run.
  - Every other severity word above the finding's own still makes the report unreadable, also in a plain sentence such as `which is a medium problem` under a low finding. The stop gate stops the agent once and names the line and the word, with the fix: write that finding as its own line, or put quoted output in backticks. A report that keeps the line stays unreadable: the lead records no verdict from it, and the sage reads it. So no higher severity is read as the lower one.
  - A quoted severity word alone (`"high"`) still counts, and so does a quote that an inch mark (`5"`) seems to open.
  - An indented line whose first or second word is a severity word is never detail, also without a list mark (`K2 medium a second bug`).
  - The stop gate of each provider names the reader's problem and the proof's problem in the one stop that it gives a review or QA agent (core's `stopReason`), so that a fix of one problem cannot leave the other one unchecked. The text of that stop lives in core once.
  - The report skill and the design page give the new rule.
- **Limits.** A count in output, such as `saw: 3 high, 2 low` under a low finding, stops once until it is put in backticks, because a writer counts real findings the same way (`2 high bugs`).
