- **Truer lines for chiefs on a shared logbook.** Each refusal and success line of a transfer now says what happened and the next step (T617). The [usage guide](docs/guide/using-sage.md#shared-logbooks) has the tables.
  - Your answer keep, or your own words, to a replace gate now prints `nothing replaced`: the task keeps its chief, no run ended, and the gate is spent. Before, the line looked like a success, so a chief could report a replacement that did not happen.
  - The chief that an offer names can decline it: it runs `cancel` with the offer's id. The offer clears, the line says that the recipient declined, and the owning chief keeps the task. Before, the recipient got a refusal that pointed to a Replace gate.
  - `projects rebuild` is your act, as `logbook repair` is, so the line that sage prints works in your terminal on a shared logbook.
  - In Claude, a `gh pr merge` event with no session id no longer skips the owner rule of a shared logbook: the merge check refuses it.
  - An ended task (merged, concluded or abandoned) of another chief on the same commit no longer bars a live task's merge.
  - A lead that meets another chief's task, or a task with no owning chief, is told to report to its chief, not to claim or open a gate.
  - A write with no chief no longer says that a hook names the id where no hook runs. An accept or a release that waits for a run names the Replace gate too, because a run of unknown status may never end.
  - The verdict refusal counts the rows of the run by severity, and its line to record a finding has `--key`, so a retry adds no second row. A stuck saved change with a damaged `decisions.tsv` prints one repair line, not two.
  - The Codex `accept` tool names `sage_read_task` for the offer's id and the version, and the `cancel` tool names the decline.
