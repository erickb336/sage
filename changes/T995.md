- **Programs are now milestones (T995).** A group of tasks for one goal is a milestone now: `milestone propose`, `task <T> set milestone=<M>`, ids `M1`, `M2`, …, the status line `milestone M5 · …`, the board's Milestones tab (`/milestones`, `/milestone/<key>`), and the Codex tool `milestone_propose`. The word "program" keeps only its meaning of a computer program, and the dictionary now has a milestone row. The README and the docs say milestone.
  - Your logbook changes once, at the first write of this version. Each program gets the next free milestone number. This project's milestones 1 to 4 have no records, so its PG1 "Sage feel" becomes M5. A decision row such as `M5 was PG1` records each new number. An open breakdown gate gets the new first line, `Approve milestone M5? No task builds before you approve.`, and still takes one answer. Your old answers and the old decision rows stay as they are. Before that write, status and the board already show the milestones. When a write stops halfway, the next write finishes the change, with the same numbers.
  - When the old table of programs (`programs.tsv` in the logbook folder) is empty or has a damaged first line, the first write refuses and changes nothing. To repair it, restore that file from a copy. Or, to accept the loss of its programs, run `logbook repair --accept-loss programs`. When a logbook from before the rename lost another table, run the repair that the refusal names.
  - After that write, an older sage in another session stops writing this logbook and says that a newer sage wrote it: update sage in each Claude Code and Codex session. Its status and board still read the logbook, without milestones.
  - The chief command that gives up a task is `unclaim` now, in Claude Code and in Codex (the `unclaim` tool), so that the word "release" is free for the release level. A takeover question now says that a chief "unclaimed" the task last.
  - The old words `program propose`, `--program`, `program=` and `release` still work for one version, and each prints a note with the new word. An old id such as `PG1` names its milestone (`M5`) there, and the line names the new id. The board sends `/programs` to the new list, and an old milestone page `/program/<key>` to the page of its new id. A board tab that was open before the update keeps its live updates. Codex has no tool under the old names.
  - `gate add` refuses a question that starts with "Approve milestone" or "Approve program", because only `milestone propose` opens a breakdown gate.
