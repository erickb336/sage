- **One change log file for each pull request.** A pull request now writes its change log entry in its own file, `changes/<task>.md` (for example `changes/T492.md`), with the date and the list item. `npm run build` puts the entries into this changelog, newest date first, and `npm run check` fails when this changelog is not what the build makes. So the entries of two pull requests no longer conflict as text: a conflict in `CHANGELOG.md` is now only in a built file, and `npm run build` ends it. The build stops, and writes nothing, when `changes/` holds a file that is not a `.md` file or when `CHANGELOG.md` holds a line that you wrote by hand, in any form; its message names the file or the line and says what to do, so no entry drops without a message. See [CONTRIBUTING.md](CONTRIBUTING.md#the-readme-and-the-docs).
