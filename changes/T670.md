- **The Claude hook refuses fewer safe commands (T670).** Each of these refusals cost the chief or an agent a workaround. The safety core stays: only the state tool writes the logbook, and a merge passes only as the plain merge command.
  - `uniq` counts as a write only with an output operand (`uniq in out`). `uniq in`, `uniq -c in` and `sort | uniq -c` only read, also of a logbook file. A uniq that another program runs (`xargs uniq`), or an operand with `$`, a backtick or a pattern, still counts as a write.
  - The word merge in the text of a program (a `node -e` or `python3` program that reads the JSON of `gh pr view`), and `git merge-tree` or `git merge-base` in a loop, no longer make a line a merge. A gh command now joins the merge text of another command only when its words have an expansion, or when its output can reach a command that runs it (a shell, `xargs`, a file, a group or a loop). Each command's own text still counts: `gh pr merge` in a loop, a chain, `bash -c`, `sh -c` or `eval`, and the GitHub API merge, are still refused.
  - A bracket group in a word keeps its `:` and `=`, so a jq slice (`.headSha[0:8]`) or a Python slice (`s[i:j]`, `sha[:8]`) no longer names a logbook file. A group that names one (`tasks.ts[v:w]`), or a class that the hook cannot read (`[[:alpha:]]`), is still refused.
  - `SAGE_HOME=$S/home/sage` in a command that writes is still refused, because the hook does not expand variables: `S` can be unset, or set to the real sage root before the line. The refusal now names the plain way: an absolute path in the scratch folder. The same holds for `SAGE_SHARED_HOME` and `CLAUDE_CONFIG_DIR`.
  - The head of a task's branch is origin's copy (`refs/remotes/origin/<branch>`) when the local branch is behind it, as after `gh pr update-branch` and a fetch. A local branch that is ahead or has diverged stays the head, and the hook moves no ref.
