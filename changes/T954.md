- **Token counts for Codex runs, and for Claude lead runs (T954).** The logbook and the board now show a token count for a Codex run, as for a Claude run. So the Codex limit "No token counts" is gone from the Codex guide.
  - At the stop of a Codex child that has its run in its task name (also a lead), the report check reads the child's own token total from its Codex session record: `total_tokens` of the last `token_usage_record` line of the child's own thread. A line of another thread does not count, and the child's own children do not count.
  - `run done` records that count as the run's tokens, with the usage source `Codex session record` and the thread as evidence. The count wins over the chief's fallback `usage unavailable`, which now stands only when the check kept no count.
  - When the record has no token line of the child, or a line that the check cannot read (not JSON, or a total that is not a whole number from 1 to 12 digits), the run's usage is unavailable, with that reason. The check never guesses a number, and it never stops the child.
  - A Claude lead run had no tokens, because the chief ended it without `--tokens` and nothing refused that. Now `run done` of a lead with a report (`done`, `blocked` or `question`) needs `--tokens`, from `subagent_tokens` in the usage of the lead's notice, as a review run needs them at `done`. A lead with no report ends as `failed` without them.
- **Limits.** Not checked in a real Codex run: that the last token line is on disk when the stop runs. A later stop of the same child replaces the count, so a line that arrives late counts at that stop.
