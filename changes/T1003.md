- **Releases (T1003).** A release is a version that you ship, such as 1.0. It holds milestones and single tasks (tasks outside a milestone), and it is optional: a logbook with no release reads and writes as before. The board does not show releases yet (T996).
  - Ask the chief to add a release: `release add --name "1.0" [--goal "<goal>"]`. The name is unique when case and width do not count, and it cannot look like an id (`T12`, `M5`), be `none`, or have a comma or a middle dot.
  - Put a milestone in a release with `milestone M5 set release=1.0`, and a single task with `task T12 set release=1.0`; `release=none` takes it out. A task of a milestone is in its milestone's release, so `task <T> set release=` refuses it and names the two ways out. A task that joins a milestone leaves its own release. Each change writes a decision row.
  - Nothing moves to another release by itself. When you say that a release ships, the chief moves each open item to the next release, one command each.
  - `status` shows one line for each release, in the order that you added them, before the milestone lines: its state (not started, in progress, done or stopped), how many of its tasks are done and stopped, its milestones, its single tasks and its goal. A milestone line names its release.
  - In Codex, the `release_add` and `milestone_set` tools do the same, and `task_set` takes `release`.
  - The move to a shared logbook takes the releases by name.
  - `release <T>`, the old word of `unclaim`, still works for this version, with its note. `release add` is the release level: a release name is never a task id, so the two do not clash.
  - Update sage in each Claude Code and Codex session before you put an item in a release. Until then an older sage writes the logbook as before. After it, an older sage still reads the logbook, but refuses every write and says that a newer sage wrote it, so no release is lost.
