- **The state tool records a review or QA verdict only when a kept report backs it.** On a task with a build, `verdict` with `review-clean`, `security-clean`, `ux-clean`, `qa-pass`, `findings` or `qa-fail` now needs `--run` with a run of that task, of the role that gives the kind, that ended done and has a kept report. The hook keeps a helper's report in the logbook (`kept/<run>.json`) when the helper stops, with the head of the task's branch: in Claude Code for each helper of a lead, and for each review or QA agent whose brief starts with `Run R<n> · task T<n>`; in Codex for the chief's own review or QA child whose task name carries its run (for example `sage_qa_t12_r40`), bound to that run when it starts. A second report of a run is not kept, and the Codex report check says so. The report needs a full 40-character head SHA, from the hook or after the word head in its BRANCH. No command keeps a report, so the chief cannot make one. A clean report backs only a clean verdict. A report with a medium or high finding backs `findings` or `qa-fail`, and a clean verdict only after each of its medium and high findings is recorded for the run and dismissed, moved or closed. The report's commit (the one that the hook saw, and each full SHA in its BRANCH) must be the verdict's `--sha`, and one run backs one verdict. Each refusal says what to do. This holds in every shell form, also with `--project=`, a relative `--project`, a glob, a variable or another letter case, because the state tool itself checks it. The checks verdicts and an investigation's `evidence-clean` did not change, and no flag skips the rule.
- **The hook's verdict rule is now only an early warning.** It refuses a command only when node runs a `sage.mjs` (in any letter case) or a path with a pattern or a variable, and it cannot read the command. A `cat`, `git log`, `git diff` or a text that names the file passes. It reads `--project` as the state tool does, also `--project=` and a relative path, and refuses a review or QA verdict when it cannot read that logbook. A lead moves its task to verifying only with a full clean cycle on the head of its branch.
- **A moved finding keeps its run.** The decision of `finding move` now names the run whose report held the finding, and its severity (`the follow-up task (from R5, medium): …`), so that the run's clean verdict counts it.
