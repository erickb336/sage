- **The arena's shared rules are now in the state tool, for both providers.** An arena judge now works on its own new branch: its run needs `--branch`, the chief names that branch at `run add` (for example `sage/t12-judge`), and the judge makes it from the chosen candidate's head and stops if it exists. For a build, the judge opens a draft pull request from that branch, and a lead takes it through the reviews and QA. For a design, the PE checks it, you approve it, and the build starts on a new branch from main. When the candidates diverge on the product, the judge reports both choices with a recommendation, the chief asks you, and a new judge run goes on with your answer. A branch has one writer, a judge too, and a branch name in another letter case counts as the same branch. While a task's arena step is open, an implementer or designer run needs `--candidate`, and a judge that ended done closes the step. The state tool refuses a judge on a candidate's branch, a candidate on a judge's branch and any other writer on a candidate's branch, in both orders, also after a run ended. The move to verified and the merge check now refuse a candidate's branch, by the pull request's head branch or, with no `--head`, by the task's `branch=`, and a task with candidates and no branch named. The rule reads the branch, not the commit, so a judge with no graft lands the candidate's commit from its own branch. Each candidate commits its artifact, saves a copy in the pages folder and opens no pull request, and the chief records the copy with `pages`. Candidate branches and pages stay until the owner deletes them, a merge deletes the branch that it lands, and worktrees go at the end of the task. Update sage before you start an arena: a judge that an older chief starts with no branch is refused, and an arena that runs during the update must finish on a new judge branch.
