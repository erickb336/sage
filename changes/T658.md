- **The move from Codex (T658).** The Codex chief can now move a project into one shared logbook, as the Claude chief can.
  - The sage MCP server has a `move` tool with the three forms of `sage move`: `preview` (true), `plan` (the 8 hex of the preview's plan) and `gate` (the move gate's id). The tool takes only these forms: a plan or a gate id in another form refuses before the state tool runs. The chief calls it with `gate` only after the owner's answer in the chat.
  - The same tool with the same gate finishes a move that stopped, also a move that the Claude chief started.
  - The Codex chief's text names the tool and its order: preview, plan, the owner's answer, gate.
  - The Codex gate counts `move` as a write, also its preview: only the chief calls the tool or runs `move` from the shell. A lead and a role agent get the usual refusal.
  - After a move, the settle step of the Codex journal closes the open fences of moved tasks. Before, it tried to void a fence whose update had committed, the journal refused that, and every later task update, preparation and assignment of the project stopped on it. The receipts stay in the old logbook, so the new logbook has none: a fence with no receipt hash is void, as before, and a fence with one is released by its own acknowledgement. The settle writes neither logbook.
  - No fence check before the move gate: the move finishes each saved change of the old logbooks first, and the settle closes each fence after the move.
