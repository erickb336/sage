- **One lead policy, in core, for Claude and Codex (T928, the owner's decision 5).** A lead's writes have one rule set in core (`lead-policy.mjs`): its short list (run add, run done, finding add, finding close, finding triage, verdict, round, pages, and task set of state, branch or pr), its own task, the round order, and the values of each command. The state tool's guard applies it to every write with `--lead`; the Claude hook and the Codex gate and state server call it too. So a lead's honest mistake gets the same plain reason in both providers: a write to another task, a command off the list, or a wrong state move.
  - The Claude hook keeps only what needs its own notes: the lead's bound slot and lead run (the own-task check), and the gap rule. Its copies of the list and of the values (`LEAD_WRITES`, `LEAD_PAIRS`) are gone. The Codex gate's `LEAD_RULES` is gone; the gate keeps only its brief check of the team's task names.
  - `pages` joins the Claude lead's list, because the Codex lead had it, and one list serves both providers.
  - The round order now holds for a Codex lead with the Claude wording, and the clean-cycle rules of a move to verifying, and back to reviewing, now hold for a Codex lead too.
  - The refusals say "the chief" where the Claude hook said "the sage".
- **Rules that T928 drops**, because each one only guards a lead that acts against its brief, or the state tool already holds it (standing orders 49 and 70):
  - The hook's own copy of the verdict backing (`backingProblem` for a lead): the state tool holds the same rule for every verdict, with the helper's kept report (T483). The way out now comes from the state tool's text.
  - "A lead uses only the runs that it added itself" for `run done`, `verdict` and `finding add --run`: a run of the lead's own task backs a verdict only with its own kept report, so an old lead's run is no risk. A lead still starts a helper only for its own run.
  - "A run whose helper gave no report ends only as failed or blocked", and the wait for a helper's lease before `run done`: such a run backs no verdict in the state tool, and a lead still does not end while a helper runs.
