- **The chief can clean up old worktrees (T927).** `sage worktrees` lists each git worktree of the project's repository with its path, branch, task, task state and one reason: merged, abandoned, branch merged, open or unknown. `sage worktrees prune --yes` then removes only the clean worktrees of a merged or abandoned task, or of a branch in origin/main, and prints each path that it removes or keeps, with the reason ([Clean up worktrees](docs/guide/using-sage.md#clean-up-worktrees)). The idea comes from pstack's worktree audit playbook.
  - A worktree matches a task only through the logbook, never through the number in a branch's name.
  - The prune keeps the primary checkout, the current worktree, a locked one, and one with uncommitted changes, untracked files or unpushed commits. A verdict SHA of the task in the ledger counts as pushed, because a squash merge deletes the task's branch on GitHub.
  - It does not fetch, and it deletes no branch. Only the chief runs it; in Codex it is the `worktrees` tool.
