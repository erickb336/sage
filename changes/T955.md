- **A reasoning effort for each Codex role (T955).** In Codex, `run_add` now prints a reasoning effort for each role and size, for example `R40 running · qa on T12 · reasoning_effort medium`. The chief and the lead give it to `spawn_agent` as `reasoning_effort`. Every Codex agent still runs on the session's model.
  - Codex reads the same model keys as Claude Code (`model.<role>`, `model.<role>.<size>`, `model.<role>.risk`), with the same model names and the same Balanced defaults, and makes the same choice. It maps the chosen name to an effort: `opus` to `high`, `sonnet` to `medium`, `haiku` to `low`. The strong Claude model gets a high effort and the light one a medium effort.
  - `fable`, `inherit`, and a role with no model key (the lead, the investigation roles) map to no effort. Then the spawn has no `reasoning_effort` field, and the agent keeps the session's effort.
  - sage never gives a Claude model name to Codex, and it gives no Codex model name. A Codex run's row in the logbook keeps no model.
  - Codex's `config` tool now takes the model keys. Codex reads them from its own config, apart from Claude's.
  - The Balanced defaults are in core now (`balancedModels`), so the two providers share one table. Claude's `run add` output and its model choice are the same as before.
  - The Codex limit "One model for all agents" now says what is still true: one model, with an effort for each role and size. The Codex guide has a new section, Model keys in Codex.
- **Limits.** Not checked in a real Codex run: a spawn with `reasoning_effort`, and the cost saving. In the bundled catalog of Codex 0.164.0, each v2 model has `low`, `medium` and `high`.
