- **sage's Codex hooks need your trust once, not after each update (T957).** The plugin declares no hooks any more. The new `hooks install` command (`node <plugin>/skills/sage/sage.mjs hooks install`) puts 7 sage entries at the end of your Codex hooks file (`~/.codex/hooks.json`) and copies a hook launcher to `~/.codex/sage-hooks`. Codex trusts such an entry by its text and its place, not by sage's files, so you trust the 7 entries once with `/hooks`, and an update runs with no new review, as in Claude Code.
  - The launcher runs the hooks of the sage version that Codex uses (`local`, else the highest version). It does nothing when sage is removed or turned off. When the installed sage cannot load, or gives no answer before the entry's timeout, it refuses only a shell merge or push.
  - Your own hooks in that file keep their places and their trust. A second `hooks install` changes nothing; it refuses a hooks file that it cannot read. `hooks status` shows the state, and `node ~/.codex/sage-hooks/launch.mjs --uninstall` removes only sage's entries and the launcher.
  - The start status names a missing or changed entry, an entry without a trust record and an old launcher, with the command that fixes each. The gate's "not running" line names the install command too.
  - The gate also refuses a shell write that names the hooks file, the launcher folder or the folder of sage's installed versions, as for Codex's config file.
  - To move to this version, run `hooks install` once and trust the 7 entries ([Update and remove](docs/guide/codex.md#update-and-remove)). The Codex guide no longer lists "hook trust after updates" as a known limit; an entry that you or another tool write with sage's command text counts as sage's (a documented limit).
  - `npm run check:codex` now runs in a scratch Codex home: it installs the entries, trusts them through the app server, swaps the plugin's version folder, and checks that each entry stays trusted.
