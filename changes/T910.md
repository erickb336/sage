- **The command reader is simpler: it no longer follows the shell forms that only a deliberate trick uses (T910, guard cleanup part 2).** By standing order 70, these forms are now documented limits: a shell function's call, the shell text of `watch`, the split string of `env -S`, and a `CDPATH` or `HOME` that the line itself changes. The reader still follows a plain `cd <dir>` (and `cd ~`), the known wrappers, `sh -c`, `eval`, `$( )`, `find -exec`, npx and `export PATH=…`.
  - After a `cd` that the reader cannot follow (`cd $X`, `cd -`), the folder of the later commands is unknown, as after an unknown `pushd`: an absolute path into a logbook root is still refused, and a push there is refused unless `git -C` names its checkout. The separate fallback readers of the logbook rule and the board rule are gone.
  - F-T909-9: the Claude board rule lets `find ~ -name '*.tmp' -delete` pass. A `find` counts as a search of the board config's folder only when it runs a program on each file (`-exec`, `-execdir`, `-ok`, `-okdir`).
  - F-T909-13: `git push --dry-run` (or `-n`) of the agent's own branch passes the push form.
  - F-T909-7: `launchctl` is a process program for agents, next to `ps` and `kill`; it passes only as a fake in the temp folder.
  - F-T909-10 and F-T909-11 are new lines in the limits list of [Rules held in code](docs/design/rules-in-code.md#the-limits-of-the-hook).
