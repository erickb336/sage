- **Keep project identity when Git is unavailable.** Both providers stop with a clear error when trusted system Git discovery fails. Project commands stop before any logbook change, including migration of an older known project list. They cannot select or initialize another logbook from a subdirectory or linked worktree. Ordinary folders outside Git repositories still work when trusted Git is available.
- **Keep the board available and scoped.** The global board stays available without Git. A project board resolves the project before it reads logbooks, so a subdirectory or worktree cannot select a different project by name.
