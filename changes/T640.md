- **The move of an existing project into one shared logbook (T640, PR 7b of the shared logbook).** Tell either chief to move the project: it shows a preview that changes nothing, then one gate.
  - `sage move --preview` prints what moves by provider, with the new numbers (Claude's first), what stays, the next numbers, the checks and the plan, a fingerprint of everything that the move writes. It refuses, with nothing changed, while a run runs, while a provider's plugin is below contract 2, and when a folder cannot be written.
  - `sage move --plan <plan>` opens the move gate. A provider with no row in `plugins.tsv` gets "move, and record it as unused" in place of "move". The preview and the gate name each other checkout that the move links, by path. A move gate answers once.
  - `sage move --gate <G>` moves after your answer: it checks the plan again under the locks, saves it, builds the new logbook, marks the old logbooks (with a backup copy of each task table), links the checkouts, counts each table by provider against the plan, and then removes the plan. A plan that no longer matches moves nothing and says what changed.
  - A move that stops: every command of the project, in Claude and in Codex, and a link, refuses and names the same command, which finishes it from any checkout of the move. A saved plan that names a folder, a logbook or a checkout that is not this repository's refuses. An end check that does not match names each missing record and the steps to set the plan aside, and no command.
  - The open tasks keep their branch and PR through adoption version 2, their findings, gates, programs and waits move with new numbers (also those of a task that they adopted, and the task numbers in a gate's question), and finished tasks, runs, verdicts and kept reports stay in the old logbooks, read-only. Codex's standing orders follow Claude's under a heading, with their lines that have no number.
  - On the board, a moved card shows its old number, for example `was Claude T640`, for the life of the task, and a banner names the move and its map page for 7 days. The restore steps end with a rename of the new logbook's folder to a dot name, so that no task shows twice.
  - A moved gate's question maps each finding key through the move, through the gate's own task first, so a move approval names the same finding; each task's round keys name its own findings, also when two tasks have the same key. A finished task with an open gate refuses the preview, which lists each such gate. A resumed plan must name the old logbook that holds its answered move gate. The move's local times carry their zone (`UTC+05:30`), and the restore step's dot name holds the plan.
  - A repair of a moved logbook's decisions writes the move's id floors again. The Codex `move` tool comes with the Codex part of the move.
