- **Chiefs and one guard for a shared logbook.** Two chiefs on one shared logbook can no longer overwrite each other's task (T604).
  - `chiefs.tsv` names each chief of the logbook. A resume keeps its session, so it is the same chief. Claude's `/clear` starts a new chief.
  - `task add` gives the task to the chief that adds it. The `chief` column of `tasks.tsv` and `runs.tsv` names it, and `claim` takes a task with no owning chief.
  - A write on a task of another chief refuses and names the owning chief. A lead acts for the chief of its lead run, on that task only. A command with no chief only reads.
  - A Claude chief adds `--chief C<n>`, and a Claude lead adds `--lead R<n>`; the hook names the id, also on a write with a quoted value. A Codex chief or lead adds nothing, and Codex has a `claim` tool.
  - The CLI, the Codex tools and the native tools `sage_update_task` and `sage_create_run` give the same refusal: it names the owning chief, or the version to claim, in the form that the reader's provider can use. A Codex tool also gives the real cause of a refusal, such as a damaged `chiefs.tsv` or a busy lock.
  - Each form of `logbook repair` is the owner's act and names no chief, so the line that a refusal prints works in the owner's terminal. The design's table had both forms under any chief.
  - An existing project shows no change: only a shared logbook has this file and this column. An older sage refuses to write a shared logbook that has the column.
