- **Two pull requests no longer conflict in the change log.** A pull request now carries only its own `changes/<task>.md`, and `npm run build` no longer writes `CHANGELOG.md`. On main, the chief runs `npm run changelog` in a small change-log pull request that changes only `CHANGELOG.md`. `npm run check` refuses a pull request that edits `CHANGELOG.md` together with other files, and requires a change-log pull request to hold exactly the build of `changes/`. Between change-log pull requests, `CHANGELOG.md` on main can lag behind `changes/`: the check then gives a warning, not a failure. So a pull request no longer needs a main merge and a new review cycle only for the change log.
