# Working on sage

- **Edit the sources only:** `principles/`, `writing/`, `preferences/`, and `packages/` (shared code and provider sources).
  - Never edit build output: `plugins/sage/`, `plugins/sage-codex/`, or `instructions/core.md`.
  - The repository keeps no history file: no `CHANGELOG.md` and no change files. A pull request description says what changed for users. At a release, the chief drafts the notes on the [releases page](https://github.com/erickb336/sage-stack/releases) from the merged pull requests and asks the owner before it publishes them (see CONTRIBUTING.md). `npm run check` fails on a `CHANGELOG.md` or a file in `changes/`.
  - Provider packages depend only on the public `sage-core` entry point. Core must not import a provider or name its models or settings.
  - One small exception: each adapter's `legacyRoots(env)` function may name each provider's logbook settings, and passes the list to core. No other adapter code names another provider's settings.
  - A provider plugin bundles core and that provider only; `scripts/providers.test.mjs` checks isolated copies.
  - The board (`packages/sage-board`) is a cross-provider reader like core: each plugin bundles it, and it may name each provider's logbook settings (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `SAGE_HOME`). Its server modules (`cli`, `install`, `pages`, `reader`, `server`) import only Node built-ins, core and `./markdown.mjs`. `markdown.mjs` is the one server file that imports a vendor package (the pinned `markdown-it`); `npm run build` bundles it into one file with its licences and a size budget. Its browser app (`packages/sage-board/app/`) may import the pinned vendor packages (React, and React Flow in the graph file that loads on demand); `npm run build` bundles it into `board/app/` of each plugin, with the vendor licences in `licenses/` and a size budget (`scripts/board-app.mjs`). No other server module imports a vendor file. `scripts/providers.test.mjs` checks the bundled copies.
  - Run `npm run build`, then `npm run check` and `npm test`. CI runs the check and the tests.
- **Principles:**
  - `ROLE_PRINCIPLES` in `packages/sage-core/roles.mjs` is the one map of each role's principles. Change it and each Claude agent's `skills:` list together; `npm run check` compares them.
  - The body is 200 words or fewer. The frontmatter has `id`, `name`, `applyWhen` and `source`.
  - A principle adapted from pstack names the pstack principle and commit in its `source`. sage keeps its own text and does not sync pstack.
  - Credit the source.
- **Skills:**
  - Use only the shared frontmatter keys: `name`, `description`, `license`, `allowed-tools`, `metadata`.
  - `name` equals the folder name.
- **Claude hooks** (`packages/sage-claude/hooks/`):
  - `claude.json` runs `sage-hook.mjs` through `launcher.mjs`. The hooks are hand-written.
  - Codex hooks live in `packages/sage-codex/hooks/`. Only verified events go in its hook manifest.
- **Sage mode:**
  - A rule that matters goes into code (the sage hook or the state tool), with a test. An instruction in a prompt alone is not enough.
  - The brief fields live in the sage hook (`BRIEF_FIELDS`) and the report fields there too (`REPORT_FIELDS`). The chief's brief template and the `report` skill must list the same fields; `npm run check` checks this.
  - The routes, states and verdict kinds live in the state tool. The design page and the chief's instructions describe them; change all three together.
- **The README's graphics** in `docs/assets/` are drawn by `scripts/graphics.mjs`, in light and dark. Change the script, then run `npm run graphics`; never edit an SVG by hand. `npm run check` checks that they match.
- **`instructions/core.md`** stays under 8 KiB, because it loads into every session (through `~/.claude/CLAUDE.md`), so each byte costs context there.
- **Write** at 80% of Simplified Technical English (`writing/ste-80.md`).
- **Words:** use sage's approved words from `writing/dictionary.md`. It builds the `dictionary` skill and the word table of `docs/guide/concepts.md`; `npm run check` fails on a flagged word.
